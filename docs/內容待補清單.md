補資料時直接改對應的 JSON 檔，跑 `node scripts/build.mjs` 就會出現在網站上。

## 1. 現職公司網站連結

`content/pages/index.json` → `experience` 區塊 → 第一筆（海密／展旭水電／耀光機電）
已經預留 `"href": ""` 欄位。**新公司網站上線後把網址填進去，公司名就會自動變成可點的連結**
（會自動加 `target="_blank"` 與 `rel="noopener noreferrer"`）。

```json
{ "role": "海密/展旭水電/耀光機電", "org": "haimi.com.tw", "href": "https://…", "period": "2014 - Current" }
```

另外兩筆（鴻海、InnoLux）是過往經歷，維持純文字不加連結。

**待確認**：InnoLux 寫「2012 - before」但鴻海也是 2012 開始，時間重疊，要不要調整。

## 2. 系統與 AI 的實作文章

決定要寫，每完成一個系統就寫一篇。一份工作三種產出：SEO 資產 → 能力證明 → Podcast 腳本。

已知可寫的題目：

- [ ] 三鐵教練系統（tri-coach）——為什麼做、資料怎麼進來、教練邏輯怎麼設計
- [ ] n8n 串接 LINE 官方帳號——實際流程、踩過的坑
- [ ] AI 監控系統——監控什麼、怎麼判斷要不要通知
- [ ] 自動化工作流——哪些行政流程被取代掉了
- [ ] 這個個人網站本身——從 Wix 搬出來的完整過程（含快照、去除依賴、部署）

**寫法建議**：做了什麼 → 為什麼做 → 怎麼做 → 卡在哪 → 現在怎樣。
不用寫成教學，寫成紀錄就好；第一手經驗才是 AI 搜尋會引用的東西。

**新增方式**：在 `content/pages/` 建 `post-xxx.json`，`"layout": "post"`。
可參考現有的 `post-學習的脈絡.json`。

## 3. 個人品牌還缺的素材

按效果排序，資料到位就能上：

| | 項目 | 需要什麼 | 放哪裡 |
|---|---|---|---|
| ① | **一句定位** | 一句話說明你幫誰解決什麼問題 | 首頁 cover 下方 |
| ② | **數字** | 累積服務人數、社團人數、Podcast 集數與收聽數 | 首頁新增 icon-grid |
| ③ | **現場照片** | 書聚現場、活動、工作室（5–10 張） | 新增 gallery 區塊 |
| ④ | **推薦語** | 書聚成員／合作方各 1–2 句 + 姓名頭銜 | 首頁或合作頁 |
| ⑤ | **作品區** | 三鐵系統、LINE 自動化、AI 監控的截圖與一段說明 | 新增 cards 區塊 |
| ⑥ | **Podcast 集數頁** | 集數清單（標題、日期、連結、重點摘要） | 新增 `/podcast` 頁 |

⑥ 的投報率特別高：既有的每一集做成一頁 show notes，等於用**已完成的工作**換到幾十個可索引頁面。

### Podcast 頁的匯入方式（工具已經寫好）

1. 找出 RSS feed 網址——瀏覽器打開
   `https://itunes.apple.com/lookup?id=1662758348&entity=podcast`，
   回傳的 JSON 裡的 `feedUrl` 就是。
2. 執行匯入：
   ```
   node scripts/import-podcast.mjs "<feedUrl>"
   ```
   會產生 `content/podcast-index.json` 與 `content/assets/podcast/`（每集封面）。
3. 把 `content/pages/_podcast.json` 改名為 `podcast.json`（拿掉底線就會被建置）。
4. `node scripts/build.mjs`。

之後每有新集數，重跑第 2、4 步就好。導覽列要不要加「Podcast」再決定。
